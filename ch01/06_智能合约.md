
在以太坊中，智能合约的表现方式是使用规定的计算机语言编程，然后编写一份代表合同的代码文件，再经过编译，变成可执行的计算机字节码。

目前以太坊智能合约的编程语言是 Solidity，采用 Solidity 语言就可以编写出各种各样的智能合约，然后将其部署到以太坊上，部署的流程是:
- 1.编写好智能合约代码文件。
- 2.经过 Solidity 编译器，将代码文件编译成十六进制码。
- 3.将编译好的十六进制码，以`以太坊交易`的形式发送到以太坊网络上。
- 4.以太坊识别出部署合约的交易，校验后，存储起来。
- 5.待合约被链下请求调用的时候，以太坊智能合约虚拟机(EVM)将编写好的智能合约代码文件编译成二进制码，并加载运行。

从部署到被运用的整个流程，产生了所谓的基于智能合约的 DApp 应用。

每一份被部署到以太坊上的智能合约都有一个唯一标识的哈希地址值，这个哈希地址值既代表用户的以太坊账户地址，又唯一标识了一份智能合约。

智能合约被部署到以太坊上后，可以通过以太坊提供的 `RPC` 接口调用能够被公共调用的智能合约函数。当然，也太坊也提供了传统的 RESTful API 的调用方式，也就是我们可以将调用智能合约的函数理解为调用服务端接口。

部署在以太坊网络上的智能合约就像部署了一个服务端程序，我们通过调用在智能合约中编写的函数可以实现各种应用，这正是以太坊智能合约的作用。

以太坊智能合约是一种对合约的统称，在此合约下，又有特别针对一类合约的标准，例如标准的代币合约标准——ERC20代币标准、ERC721标准等。

### ERC20 标准

ERC20 标准的官方解析看[这里](https://github.com/ethereum/EIPs/blob/master/EIPS/eip-20.md)

ERC20 标准是一种软性强制的标准，被专门用来发布虚拟货币，标准中包括了成员变量、函数和事件等，以方便开发者调用。目前很多的以太坊钱包软件在设定进行代币转账时，默认使用 ERC20 标准的函数名称和传参类型。

1.标准的成员变量

ERC20 标准规定了智能合约在使用 Solidity 语言编程时可以通过下述形式来定义成员变量:
- string public name
- string public symbol
- uint8 public decimals
- uint256 public totalSupply

name 一般表示当前代币的名称，例如 My First Token。

symbol 表示当前代币的符号，代表的是一种简称，例如可以取 name 的首字母来设置，My First Token 的 symbol 就是 MFT。

decimals 表示将代币单位精确到小数点后多少位，比如总量(totalSupply)初始化为 1000，decimal 为 1(即代币单位精确到小数点后 1 位，也就是 0.1)，则实际是 100 个代币。如果你要从钱包中向别人发送 1 个代币，不能写 1，而要写 10。如果你要发行 1000 个代币，那么在智能合约中的初始设置应该是 `1000×10^decimals`(即要乘上 10 的 decimals 次方)。

totalSupply 代表当前代币的总发行量。

2.标准的函数

ERC20 标准规定了智能合约须具备并实现下面的函数及事件(Event):
```sol
  contract ERC20 {
    function totalSupply() constant returns (uint256 totalSupply);
    funciton balanceOf(address _owner) constant returns (uint256 balance);
    
  }
```
