### 环境要求

运行一个以太坊节点需要执行端、执行端等多方的参与，其中执行端对环境的要求相对其他而言，更高。

运行一个 Geth 节点的硬件要求取决于节点配置，在时间上可以随着网络升级的实施进行改变。以太坊节点可以运行在低功耗、资源有限的设备上，例如树莓派。

1.处理器

最好使用四核(或双核超线程)CPU。Geth 适用于多种架构。

2.内存

建议至少 16GB 的 RAM。

3.磁盘空间

磁盘空间通常是节点运行的主要瓶颈。就以太坊主网而言，截至2022年9月，建议为运行 Geth 和共识客户端的全节点配备 2TB SSD。Geth 本身对于快照同步的全节点需要超过 650GB 的磁盘空间，并且使用默认缓存大小，每周增长约 14GB。修剪操作会将总存储空间降至原来的 650GB。存档节点需要额外的空间。一个"完整"存档节点(保存所有创世状态)需要超过 12TB 的空间。也可以通过在初始同步后关闭垃圾收集器来创建部分存档节点——存储需求取决于保存的状态量。

除了存储容量之外，Geth 节点还依赖于快速的读写操作。这意味着 HDD 和价格较低的 SSD 有时难以同步区块链。

如果是以太坊测试网或者在本地搭建的私网而言，要求可以放宽一些。

4.带宽

拥有稳定可靠的网络连接至关重要，尤其是在运行验证器时，因为宕机可能会导致错过奖励或受到惩罚。建议运行节点的下载速度至少为 25Mbps。运行节点还需要上传和下载大量数据，因此最好使用没有流量上限的 ISP。

5.安装

本地计算机的防火墙设置应:
- 阻止所有到 8545 端口的流量，或任何为 JSON-RPC 请求定义的自定义端口，但来自明确定义的受信任计算机的流量除外。
- 允许 TCP 30303 端口或任何为点对点通信定义的自定义端口上的流量。这允许节点连接到对等节点。
- 允许 UDP 30303 端口或任何为点对点通信定义的自定义端口上的流量。这允许节点发现。

接下来以 Linux 系统示例，说明以太坊的安装和配置。

### Geth

选择最新版本 1.16.5。

进入 Linux 对应的下载页面后，选择指定版本进行下载。下载后的压缩包名称是 geth-linux-amd64-1.16.5-737ffd1b.tar.gz。

在 Linux 上将文件解压到`~/geth-home`目录下。解压后的文件组织形式如下:
```s
geth-home
└── geth-linux-amd64-1.16.5-737ffd1b
    ├── COPYING
    └── geth
```

将下面的命令添加到`~/.bashrc`配置中，执行`source ~/.bashrc`使指令生效。
```s
  export PATH=$HOME/geth-home/geth-linux-amd64-1.16.5-737ffd1b:$PATH
```
执行`geth -h`确认是否有帮助信息。

### Lighthouse

选择最新版本 8.0.1。

进入下载页面后，选择指定版本下载。下载后的文件名称是 lighthouse-v8.0.1-x86_64-unknown-linux-gnu.tar.gz。

将文件解压后，只有一个名称为"lighthouse"的可执行文件，将该文件同样放到上面的"$HOME/geth-home/geth-linux-amd64-1.16.5-737ffd1b"路径下。

### Clef

有些压缩包仅包含 geth，而其他压缩包则包含 geth 和各种开发者工具(clef、devp2p、abigen、bootnode、evm 和 rlpdump)。

如果压缩包中只 geth 文件，可以采用源码编译的方式生成 clef 文件。

首先确认安装了 go 环境(Geth v1.16.5版本要求 go 版本为 1.23 及以上)，笔者安装的 go 版本为 `1.25.3`。

克隆[go-ethereum仓库](https://github.com/ethereum/go-ethereum)，切换到指定版本。

go-ethereum 项目附带了 cmd 目录中的几个包装器/可执行文件，这些开发者工具(clef、devp2p、abigen、bootnode、evm 和 rlpdump)都可以通过运行`make all`进行编译:
```s
  git clone https://github.com/ethereum/go-ethereum
  cd go-ethereum
  git checkout v1.16.5
  make all
```
这些命令会在 go-ethereum/build/bin 文件夹中创建一系列可执行文件，其中就包括"clef"文件。这些二进制文件是独立的，不需要任何其他文件。如果需要，可以将其移动到另一个目录并运行。

Clef 并不依赖于 Geth，所以也可以使用以下方式自行构建:
```s
  make clef
```

这里将 clef 文件也放到上面的"$HOME/geth-home/geth-linux-amd64-1.16.5-737ffd1b"路径下。

除了 geth 和 clef 命令，其他命令的说明如下:
- `devp2p`: 无需运行完整的区块链即可与网络层上的节点进行交互的实用程序。
- `abigen`: 源代码生成器，用于将以太坊合约定义转换为易于使用、编译时类型安全的 Go 包。它适用于普通的[以太坊合约 ABI](https://docs.soliditylang.org/en/develop/abi-spec.html)，如果合约字节码可用，则可进行扩展功能。此外，它也接受 Solidity 源文件，从而大大简化开发流程。详情请参阅我们的[原生 DApps 页面](https://geth.ethereum.org/docs/developers/dapp-developer/native-bindings)。
- `evm`: EVM(以太坊虚拟机)的开发者实用程序版本，能够在可配置的环境和执行模式下运行字节码片段。其目的是允许对 EVM 操作码进行隔离、细粒度的调试(例如 `evm --code 60ff60ff --debug run`）。
- `rlpdump`: 开发人员实用工具，用于将二进制 RLP([Recursive Length Prefix](https://ethereum.org/developers/docs/data-structures-and-encoding/rlp/),递归长度前缀)转储(以太坊协议在网络和共识方面使用的数据编码)转换为更用户友好的分层表示(例如 `rlpdump --hex CE0183FFFFFFC4C304050583616263`）。
