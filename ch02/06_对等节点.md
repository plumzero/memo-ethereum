Geth 的默认行为是连接到以太坊主网。但是，Geth 也可以连接到公共测试网、[私有网络](https://geth.ethereum.org/docs/fundamentals/private-network)和[本地测试网](https://geth.ethereum.org/docs/developers/dapp-developer/dev-mode)。

### 寻找对等网络

Geth 会不断尝试连接到网络上的其他节点，直到拥有足够多的对等节点。如果路由器上启用了 UPnP (通用即插即用)或以太坊运行在面向互联网的服务器上，它也会接受来自其他节点的连接。Geth 使用[发现协议](https://ethereum.org/developers/docs/networking-layer/#discovery)查找对等节点。在发现协议中，节点交换连接详细信息，然后建立会话([RLPx](https://github.com/ethereum/devp2p/blob/master/rlpx.md))。如果节点支持兼容的子协议，它们就可以开始[在线上](https://ethereum.org/developers/docs/networking-layer/#wire-protocol)交换以太坊数据。

首次加入网络的新节点会由引导节点（"bootnode"）引入一组对等节点，该节点的唯一目的是将新节点连接到对等节点。这些引导节点的端点已硬编码到 Geth 中，但也可以通过在启动时提供 `--bootnode` 标志以及以逗号分隔的 [enodes](https://ethereum.org/developers/docs/networking-layer/network-addresses/#enode) 形式的引导节点地址来指定它们。例如:
```s
  geth --bootnodes enode://pubkey1@ip1:port1,enode://pubkey2@ip2:port2,enode://pubkey3@ip3:port3
```

在某些情况下，禁用发现过程很有用，例如运行本地测试节点或具有已知固定节点的实验性测试网络。这可以通过在启动时向 Geth 传递`--nodiscover`标志来实现。

### 连接问题

Geth 有时会无法连接到对等节点。常见原因如下:
- 本地时间可能不正确。加入以太坊网络需要精确的时钟。可以使用 `sudo ntpdate -s time.nist.gov` 等命令重新同步本地时钟（具体操作取决于操作系统）。
- 某些防火墙配置可能会禁止 UDP 流量。您可以使用控制台上的静态节点功能或 `admin.addPeer()` 手动配置连接。
- 在轻量模式下运行 Geth 通常会导致连接问题，因为运行轻量服务器的节点很少。除了将 Geth 切换出轻量模式外，没有其他简单的解决方法。请注意，轻量模式目前不适用于权益证明网络。
- Geth 连接的公共测试网络可能已被弃用，或者活跃节点数量较少且难以找到。在这种情况下，最好的做法是切换到其他测试网络。

### 检查连接

`net` 模块有两个属性，允许从交互式 JavaScript 控制台检查节点连接性。一个是`net.listening`，用于报告 Geth 节点是否正在监听入站请求; 另一个是`peerCount`，用于返回节点连接到的活动对等体的数量。
```s
> net.listening
true

> net.peerCount
3
```

### 自定义网络

对于开发者来说，连接到私有测试网络(而非公共测试网或以太坊主网)通常很有用。这些沙盒环境允许在不与其他矿工竞争的情况下创建区块，轻松铸造测试以太币，并允许自由地进行破坏而不会产生任何实际后果。通过为`--networkid`提供一个未被任何其他现有公共网络([Chainlist](https://chainlist.org/))使用的值，并创建自定义的`genesis.json`文件来启动私有网络。有关此操作的详细说明，请参阅[私有网络页面](https://geth.ethereum.org/docs/fundamentals/private-network)。

### 静态节点

Geth 还支持静态节点。静态节点是指始终保持连接的特定对等体。Geth 重启后会自动重新连接到这些对等体。通过将特定节点的 enode 地址添加到配置文件中，可以将这些节点定义为静态节点。创建此配置文件的最简单方法是运行以下命令:
```s
  geth --datadir <datadir> dumpconfig > config.toml
```

这将在当前目录中创建`config.toml`文件。然后，用户可以将静态节点的 enode 地址以列表形式添加到`config.toml`文件`Node.P2P`部分的`StaticNodes`字段中。启动 Geth 时，传递`--config config.toml`参数。config.toml 文件中的相关行如下所示:
```s
  StaticNodes = ["enode://f4642fa65af50cfdea8fa7414a5def7bb7991478b768e296f5e4a54e8b995de102e0ceae2e826f293c481b5325f89be6d207b003382e18a8ecba66fbaf6416c0@33.4.2.1:30303"]
```

在启动 Geth 之前，请确保 config.toml 中的其他行也已正确设置，因为传递`--config`参数会指示 Geth 从此文件获取其配置值。完整的 config.toml 文件示例可在此处找到。

用户也可以在运行时在 JavaScript 控制台中通过将 enode 地址传递给 `admin.addPeer()` 来添加静态节点:
```s
admin.addPeer(
  'enode://f4642fa65af50cfdea8fa7414a5def7bb7991478b768e296f5e4a54e8b995de102e0ceae2e826f293c481b5325f89be6d207b003382e18a8ecba66fbaf6416c0@33.4.2.1:30303'
);
```

### 对等网络限制

有时需要限制 Geth 连接的对等节点数量，以限制运行节点所需的计算和带宽成本。默认情况下，限制为 50 个对等节点，但可以通过将值传递给`--maxpeers`来更新此限制:
```s
  geth <otherflags> --maxpeers 15
```

### 可信节点

可以将受信任节点添加到 config.toml 中，方法与静态节点相同。在使用`--config config.toml`启动 Geth 之前，将受信任节点的 enode 地址添加到 config.toml 中的`TrustedNodes`字段。

可以在 JavaScript 控制台中使用`admin.addTrustedPeer()`调用添加节点，并使用`admin.removeTrustedPeer()`调用删除节点。
```s
admin.addTrustedPeer(
  'enode://f4642fa65af50cfdea8fa7414a5def7bb7991478b768e296f5e4a54e8b995de102e0ceae2e826f293c481b5325f89be6d207b003382e18a8ecba66fbaf6416c0@33.4.2.1:30303'
);
```
