Geth 是一个[执行客户端](https://ethereum.org/glossary/#execution-client)。历史上，仅一个执行客户端就足以运行一个完整的以太坊节点。然而，自从以太坊从工作量证明(PoW)转换为基于权益证明(PoS)的共识机制以来，Geth 需要与另一个称为"共识客户端"的软件耦合。

目前有五种可用的共识客户端，它们都以相同的方式连接到 Geth。本页将概述如何将 Geth 与共识客户端一起设置，以组成一个完整的以太坊节点。

> 另外，也可以在非生产环境下使用集成的 Beacon Light 客户端。请参阅[本指南](https://geth.ethereum.org/docs/fundamentals/blsync)。

### 配置 Geth

为了连接到共识客户端，Geth 必须公开一个用于客户端间 RPC 连接的端口。

RPC 连接必须使用 `jwtsecret` 文件进行身份验证。该文件默认创建并保存在 `<datadir>/geth/jwtsecret` 中，但您也可以创建并保存到自定义位置，或者自行生成该文件，并通过将文件路径传递给 `--authrpc.jwtsecret` 将其提供给 Geth。Geth 和共识客户端都需要 `jwtsecret` 文件。

然后，必须将授权应用于特定的地址/端口。这可以通过将地址传递给 `--authrpc.addr` 并将端口号传递给 `--authrpc.port` 来实现。您也可以安全地将 `localhost` 或通配符 `*` 传递给 `--authrpc.vhosts`，这样 Geth 就会接受来自虚拟主机的传入请求，因为它只适用于使用 `jwtsecret` 进行身份验证的端口。

启动 Geth 以便它可以连接到共识客户端的完整命令如下:
```s
  geth --authrpc.addr localhost --authrpc.port 8551 --authrpc.vhosts localhost --authrpc.jwtsecret /tmp/jwtsecret
```

### 共识客户端

目前有五个共识客户端可以与 Geth 一起运行。它们是:
- [Lighthouse](https://lighthouse-book.sigmaprime.io/): 用 Rust 编写
- [Nimbus](https://nimbus.team/): 用 Nim 编写
- [Prysm](https://prysm.offchainlabs.com/docs/): 用 Go 编写
- [Teku](https://consensys.io/teku) 用 Java 编写
- [Lodestar](https://lodestar.chainsafe.io/): 用 Typescript 编写

建议在选择共识客户端时考虑[客户端的多样性](https://ethereum.org/developers/docs/nodes-and-clients/client-diversity/)。每个客户端的安装说明请参阅上述列表中链接的文档。

共识客户端必须使用正确的端口配置启动，才能与本地 Geth 实例建立 RPC 连接。在上面的示例中，`localhost:8551` 已获得授权。所有共识客户端都有一个类似于 `--http-webprovider` 的命令，该命令以公开的 Geth 端口作为参数。

共识客户端还需要 Geth 的 `jwt-secret` 路径，以便对它们之间的 RPC 连接进行身份验证。每个共识客户端都有一个类似于 `--jwt-secret` 的命令，该命令以文件路径作为参数。这必须与提供给 Geth 的 `--authrpc.jwtsecret` 路径一致。

所有共识客户端都公开了一个 [Beacon API](https://ethereum.github.io/beacon-APIs/)，可用于检查 Beacon 客户端的状态，或通过使用 [Curl](https://curl.se/) 等工具发送请求来下载区块和共识数据。更多信息请参阅每个共识客户端的文档。

### 验证者

验证者负责保护以太坊区块链的安全。验证者已将至少 32 ETH 质押到存款合约中，并运行验证器软件。每个共识客户端都有各自的验证器软件，并在其各自的文档中进行了详细描述。处理质押和验证器密钥生成的最简单方法是使用以太坊基金会[质押启动板(Staking Launchpad)](https://launchpad.ethereum.org/en/)。启动板将指导用户完成生成验证器密钥以及将验证器连接到共识客户端的过程。

### 同步

在连接的共识客户端同步之前，Geth 无法同步。这是因为 Geth 需要一个目标头来同步。同步共识客户端的最快方法是使用检查点同步。为此，可以在启动时向共识客户端提供检查点或检查点提供程序的 URL。这些检查点有多个来源。理想的情况是从受信任的节点运营商处获取一个，以带外方式组织，并针对第三个节点、区块浏览器或检查点提供程序进行验证。一些客户端还允许通过 HTTP API 访问现有的 Beacon 节点来同步检查点。此外，还有几个[公共的检查点同步端点](https://eth-clients.github.io/checkpoint-sync-endpoints/)。

有关同步的更多详细信息，请参阅[同步页面](https://geth.ethereum.org/docs/fundamentals/sync-modes)。有关故障排除，请参阅[控制台日志消息页面](https://geth.ethereum.org/docs/fundamentals/logs)上的"同步"部分。

### 使用 Geth

Geth 是用户向以太坊发送交易的门户。Geth Javascript 控制台可用于此目的，并且大多数 [JSON-RPC API](https://geth.ethereum.org/docs/interacting-with-geth/rpc) 仍将通过 web3js 或 HTTP 请求(以 JSON 格式发送命令)提供。这些选项的详细说明请参阅 [Javascript 控制台页面](https://geth.ethereum.org/docs/interacting-with-geth/javascript-console)。您可以在单独的终端中使用以下命令启动 Javascript 控制台(假设 Geth 的 IPC 文件保存在 datadir 中):
```s
  geth attach datadir/geth.ipc
```

### 小结

鉴于以太坊已实现权益证明(PoS)，Geth 用户必须安装并运行共识客户端。否则，Geth 将无法追踪链头。目前有五种共识客户端可供选择。本页面概述了如何选择共识客户端以及如何配置 Geth 连接到该客户端。
