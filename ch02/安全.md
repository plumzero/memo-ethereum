### 下载 Geth

使用[下载页面](https://geth.ethereum.org/downloads)上的链接下载 Geth。下载文件的 SHA256 哈希值可用于确认与我们的版本完全一致。这可以防止恶意代码被无意中从敌对来源下载。下载可信共识客户端软件时也应采取同样的措施。

### 网络安全

本地计算机的防火墙设置应:
- 阻止所有到 8545 端口的流量，或任何为 JSON-RPC 请求定义的自定义端口，但来自明确定义的受信任计算机的流量除外。
- 允许 TCP 30303 端口或任何为点对点通信定义的自定义端口上的流量。这允许节点连接到对等节点。
- 允许 UDP 30303 端口或任何为点对点通信定义的自定义端口上的流量。这允许节点发现。

### API 安全

Geth 拥有多个 API 端点: 旧版 json-rpc、全新可信"Beacon" json-rpc API 以及 graphql 端点。这些端点均无法抵御恶意客户端的攻击，也无法处理海量客户端/流量。

将 API 端点暴露给"互联网"或任何不受信任/恶意网络:
- 会增加因 OOM 导致崩溃的风险
- 会增加因资源匮乏(IO 或 CPU)而无法跟上区块链进度的风险
- 会增加通过虚假签名请求(取决于暴露的命名空间)窃取资金的风险

我们不建议公开 API 端点，任何希望公开 API 端点的用户都应仔细考虑设置代理、WAF、应用程序级过滤、速率限制、日志记录、TLS 终止器和监控，以提高弹性。

### 账户安全

账户安全的关键在于妥善备份私钥和账户密码，使其无法被攻击者获取。用户需对此负责。Geth 提供密钥加密存储，密钥需使用账户密码解锁。如果密钥文件或密码丢失，账户将无法访问，资金也将永久丢失。如果攻击者获取了未加密密钥的访问权限，他们就将控制与账户相关的所有资金。

Geth 内置账户管理工具。然而，我们推荐使用 Clef 作为外部账户管理和签名工具。它可以与 Geth 分离运行，甚至可以在专用的安全外部硬件(例如虚拟机或安全 USB 驱动器)上运行。这被认为是最佳实践，因为除非实施了特定的预定义规则，否则用户需要手动审查所有涉及敏感数据的操作。签名在 Clef 本地完成，而不是将密钥访问权限授予节点。Geth 的内置管理工具计划在不久的将来弃用。

安全可靠地备份您的密钥库和密码！

### 其他安全考虑

即使节点绝对安全，用户仍然可能被攻击者操纵，暴露安全漏洞或无意中与不安全的智能合约进行交互。有关概述，请参阅以太坊[安全最佳实践网页](https://ethereum.org/security/)和[智能合约安全](https://ethereum.org/developers/docs/smart-contracts/security/)简介。
