Geth 使用名为 Clef 的外部签名器来管理账户。Clef 是一个独立运行的软件，独立于 Geth 实例运行，但会连接到 Geth 实例。Clef 负责账户创建、密钥管理以及交易/数据签名。本节介绍如何使用 Clef 创建和管理 Geth 账户。

### 初始化 Clef

首次使用 Clef 时，需要使用一个用于解锁 Clef 安全库的主种子(master seed)以及库的路径进行初始化。Clef 将使用库来存储密钥库的密码、JavaScript 自动签名规则以及规则文件的哈希值。

执行 `clef init` 初始化，默认库路径为`~/.clef`。也可以通过 `--configdir` 指定库路径，例如:
```s
  clef init --configdir /home/user/go-ethereum/clefdata
```
记住主种子并妥善保管至关重要。它允许访问 Clef 管理的账户。

### 连接 Geth 和 Clef

Clef 和 Geth 应该分别启动，但配置要互补，以便它们能够通信。这需要让 Clef 知道 Geth 将要连接的网络的 `chain_id`，以便将此信息包含在任何签名中。Clef 还需要知道存储账户的密钥库的位置(或将要存储的位置)。该位置通常位于 Geth 数据目录的子目录中。Clef 还提供了一个数据目录，该目录通常也放置在 Geth 数据目录中。为了使用 Curl 与 Clef 通信，可以传递 `--http` 参数，这将默认在 `localhost:8550` 上启动一个 HTTP 服务器。要启动配置为连接到 Sepolia 测试网的 Geth 节点的 Clef，请执行以下操作:
```s
  clef --chainid 11155111 --keystore ~/geth-home/keystore --configdir ~/.clef --http
```

Clef 将开始在终端中运行，首先出现免责声明并提示单击"ok":
```s
WARNING!

Clef is an account management tool. It may, like any software, contain bugs.

Please take care to
- backup your keystore files,
- verify that the keystore(s) can be opened with your password.

Clef is distributed in the hope that it will be useful, but WITHOUT ANY WARRANTY;
without even the implied warranty of MERCHANTABILITY or FITNESS FOR A PARTICULAR
PURPOSE. See the GNU General Public License for more details.

Enter 'ok' to proceed:
>
```

Geth 可以在单独的终端中启动。要连接到 Clef，请确保数据目录与提供给 Clef 的路径一致，并传递 Clef IPC 文件的位置(Clef 会将其保存到其 `--configdir` 标志提供的路径中)，在本例中，我们将其设置为`~/.clef/clef.ipc`:
```s
  geth --sepolia --datadir sepolia <other flags> --signer=.clef/clef.ipc
```

请记住，还需要运行一个共识客户端，这需要向 Geth 提供 `--http` 和几个 `authrpc` 值。本 [Gist](https://gist.github.com/jmcook1186/ea5de9215ecedb1b0105bcfa9c30d44c) 提供了 Geth-Lodestar 客户端组合以及 Clef 的完整启动命令示例 - 可根据不同的客户端组合和配置进行调整。

### 与 Clef 交互

与 Clef 的交互有两种模式。一种是直接交互，即通过 HTTP 或 IPC 传递请求，并使用 Clef 外部 API 中定义的 JSON-RPC 数据。这种方式可以在 Clef 中执行一些不需要 Geth 的操作，例如创建和列出账户，或离线签名数据。另一种方式是通过 Geth。如果 Geth 以 Clef 作为外部签名器启动，那么与账户数据相关的 Geth 请求将通过 Clef 进行审批。默认情况下，用户在出现提示时，通过在 Clef 控制台中输入 `y` 或 `n` 来手动批准或拒绝交互，但也可以创建自定义规则来自动执行常见任务。

1.创建账户

可以使用 Clef 的 `newaccount` 方法创建新帐户。这将生成一对新的密钥对并将其添加到给定的密钥库目录中:
```s
  clef newaccount --keystore ~/geth-home/keystore
```
Clef 将在终端中请求新密码。

使用原始 JSON 请求也可以实现同样的效果(本例使用 curl 将请求发送到 Clef 公开的 HTTP 端口):
```s
  curl -X POST --data '{"id": 0, "jsonrpc": "2.0", "method": "account_new", "params": []}' http://localhost:8550 -H "Content-Type: application/json"
```
由于 Clef 正在等待手动批准，控制台将挂起。切换到 Clef 终端并批准该操作。Clef 将提示输入账户密码，然后在终端日志中确认账户创建。新的密钥文件已添加到 `~/geth-home/keystore` 中的密钥库中。JSON 响应将返回到发起请求的终端，并在`result`字段中包含新的账户地址。
```s
  {"jsonrpc":"2.0","id":0,"result":"0xcc16f6127e14b5a590c0e3f4a1719f98cf6f0b7e"}
```
安全可靠地备份帐户密码至关重要，因为它无法检索或重置。

> 注意: 如果创建帐户时提供的密码丢失或忘记，将无法找回，帐户将永远处于锁定状态。密码必须安全可靠地备份！备份密钥库并牢记密码至关重要！

新生成的密钥文件可以在 `~/geth-home/keystore/` 中查看。文件命名格式为 `UTC--<date>--<address>`，其中 `date` 是密钥创建的日期和时间，采用 [UTC 8601](https://www.iso.org/iso-8601-date-and-time-format.html) 格式，时间偏移为零，秒数精确到小数点后八位。`address` 是组成账户地址的 40 个十六进制字符，不带前导 `0x`，例如:
```s
  UTC--2025-10-28T02-18-12.515327853Z--cc16f6127e14b5a590c0e3f4a1719f98cf6f0b7e
```

还可以通过使用 `clef importraw` 导入原始私钥(十六进制字符串)来创建帐户，如下所示:
```s
  clef importraw <hexkey>
```

终端将回复以下消息，表明帐户已成功创建:
```s
## Info
Key imported:
  Address 0x9160DC9105f7De5dC5E7f3d97ef11DA47269BdA6
  Keystore file: ~/geth-home/keystore/UTC--2022-10-28T12-03-13.976383602Z--9160dc9105f7de5dc5e7f3d97ef11da47269bda6

The key is now encrypted; losing the password will result in permanently losing
access to the key and all associated funds!

Make sure to backup keystore and passwords in a safe location.
```

2.列出账户

可以使用简单的 CLI 命令将密钥库中的帐户列到终端，如下所示:
```s
  clef list-accounts --keystore ~/geth-home/keystore
```

或者在 POST 请求中使用 `account_list`，如下所示:
```s
  curl -X POST --data '{"id": 0, "jsonrpc": "2.0", "method": "account_list", "params": []}' http://localhost:8550 -H "Content-Type: application/json"
```
这将返回一个 JSON 对象，其中包含`result`字段中数组中的帐户地址。
```json
{"jsonrpc":"2.0","id":0,"result":["0xb41b73fe5f4112329dd14ead6132b7b481fcd2b3","0x5709fbdacde2bc10743af51fdb9e3c514e0ed09f","0xcc16f6127e14b5a590c0e3f4a1719f98cf6f0b7e"]}
```
账户的列出顺序是按字典顺序排列的，但由于文件名中包含时间戳，因此实际上是按创建时间顺序排列的。在以太坊节点之间传输整个密钥库目录或单个密钥文件是安全的。这一点很重要，因为当从其他节点添加账户时，密钥库中账户的顺序可能会发生变化。因此，不要依赖脚本或代码片段中的账户索引。

还可以使用 `eth.accounts` 在 Javascript 控制台中列出帐户，这将提交给 Clef 审批。

除了个人账户之外，还可以通过 `list-wallets` 命令列出由 Clef 管理的任何钱包(这还将打印钱包状态以及它们包含的任何账户的地址和 URl)。
```s
  clef list-wallets --keystore ~/geth-home/keystore
```
笔者这里的返回是:
```s

  -Account 0: 0xb41B73fE5F4112329dD14EaD6132b7B481FCd2B3 (keystore:///home/tester/geth-home/keystore/UTC--2025-10-27T08-57-55.363156022Z--b41b73fe5f4112329dd14ead6132b7b481fcd2b3)

  -Account 0: 0x5709FBdACde2BC10743Af51fDB9e3C514e0Ed09f (keystore:///home/tester/geth-home/keystore/UTC--2025-10-27T08-59-12.305288654Z--5709fbdacde2bc10743af51fdb9e3c514e0ed09f)
```

3.导入私钥

也可以通过导入现有私钥来创建账户。例如，用户可能已经在使用浏览器钱包创建的地址中拥有一些以太币，现在希望使用新的 Geth 节点来管理他们的资金。在这种情况下，可以从浏览器钱包导出私钥并将其导入 Geth。可以使用 Clef 来实现，但目前该方法尚未对外公开，​​需要实现 UI。Geth GitHub 上有一个 Python UI 可以用作示例，或者也可以使用默认的控制台 UI 来完成。但是，目前，从私钥导入账户最直接的方法是使用 Geth 的账户导入功能。

Geth 要求将私钥存储为一个文件，该文件包含未加密的正则椭圆曲线字节，并以十六进制编码（即不带前导 0x 的纯文本密钥）。新帐户将以加密格式保存，并受用户请求时提供的密码保护。与往常一样，此密码必须安全可靠地备份——如果忘记，将无法检索或重置！
```s
  geth account import --datadir ~/geth-home ./keyfile
```
终端中会显示如下信息，表示导入成功:
```s
Please enter a passphrase now.
Passphrase:
Repeat Passphrase:
Address: {7f444580bfef4b9bc7e14eb7fb2a029336b07c9d}
```
对于在 Geth 实例之间转移帐户的用户来说，此导入/导出过程并非必需，因为密钥文件可以直接从一个密钥库复制到另一个密钥库。

您还可以在非交互模式下导入帐户，方法是将帐户密码以纯文本形式保存在 `.txt` 文件中，并在启动时使用 `--password` 标志传递其路径。
```s
  geth account import --password path/password.txt path/keyfile
```

在这种情况下，务必确保密码文件仅供目标用户读取。这可以通过更改文件权限来实现。在 Linux 上，以下命令可更新文件权限，确保只有当前用户才能访问:
```s
chmod 700 /path/to/password
cat > /path/to/password
<type password here>
```

4.导入钱包

假设密码已知，导入预售钱包非常简单。使用 Geth 的钱包导入命令，将路径传递到钱包。
```s
  geth wallet import /path/to/presale.wallet
```

### 更新账户

Clef 可用于设置和删除现有密钥库文件的密码。要设置新密码，请将帐户地址传递给 `setpw`:
```s
  clef setpw cc16f6127e14b5a590c0e3f4a1719f98cf6f0b7e
```
这将导致 Clef 提示输入新密码(两次)，然后输入 Clef 主密码来解密密钥文件。

Geth 的 `account update` 子命令也可以用来更新账户密码:
```s
  geth account update cc16f6127e14b5a590c0e3f4a1719f98cf6f0b7e
```

或者，在非交互模式下，可以使用 `--password` 标志传递包含未加密纯文本的帐户密码的密码文件的路径:
```s
  geth account update cc16f6127e14b5a590c0e3f4a1719f98cf6f0b7e --password path/password.txt
```
使用 `geth account update` 命令更新账户会将原始文件替换为新文件——这意味着原始文件在更新后将不再可用。此命令可用于将密钥文件更新为最新格式。

### 解锁账户

使用 Clef，无差别解锁账户不再是一项功能。取而代之的是，Clef 解锁操作将被锁定，直到用户明确手动批准操作为止，除非这些操作符合已编码在规则集中的某些特定场景。请参阅我们的 Clef 文档，了解如何创建规则集。

交易可以通过原始 JSON 请求发送到 Geth，也可以在 JavaScript 控制台中使用 `web3js` 发送。无论哪种方式，由于 Clef 充当签名者，因此交易只有在 Clef 批准后才会发送。以下代码片段展示了如何使用 JavaScript 控制台在密钥库中的两个账户之间发送交易。
```s
var tx = {from: eth.accounts[1], to: eth.accounts[2], value: web3.toWei(5, "ether")}

# this will hang until approval is given in the Clef console
eth.sendTransaction(tx)
```

### 小结

本节演示了如何使用 Clef 和 Geth 的账户管理工具来管理账户。账户信息通过密码加密存储。务必安全可靠地备份账户密码和密钥库目录。
